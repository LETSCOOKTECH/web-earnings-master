# 02 — AEO answer quality and real user task completion

AEO is making human questions answerable accurately, with evidence and context, while maintaining the actual function when a tool is needed. It is NOT creating many AI FAQ pages, exact-word repetitions, or claiming Featured Snippet/AI Mode selection from code.

## Question -> job -> evidence
For each genuine query or customer question: user task, region/language/device, input, objective correct answer or output, time-sensitive scope, original fact source, limitation, and counterexample. Classify factual, explanatory, calculation, troubleshooting, comparisons, purchasing, local and actionable tool jobs. A useful file converter needs a real correct downloadable result, not just text about conversion.

## Answer format
Give the direct correct answer prominently WHEN it helps. Keep necessary exceptions, data version, date, units, price/health/legal caveats and method; don't truncate correctness for a snippet. Provide actual examples, input-output fixtures and reproducible studies or original benchmarks. Cite real authoritative sources when meaningful. Clearly separate user-provided, sampled and externally verified facts. Use descriptive visible headings, lists and paragraphs where useful, not for AI microchunk hacks.

## Frontend accessibility and on-page mapping
Render meaningful HTML initially with semantic H1/sections/links, readable source methodology and stable tool actions. Responsive, keyboard/assistive labels and error/status states, with actual independent output verification. Natural title/H1/intro and relevant related real pages are useful; keyword stuffing, phantom pages and automatically spun locality variants can violate Search spam policies. No magic density, meta keywords or forced long-word pages.

## Rich results and snippets
Provider chooses Featured Snippets, People Also Ask and answer citations. Schema.org FAQPage does NOT make Google show an FAQ rich result; Google's FAQ Search rich result was retired in 2026. Only use appropriate current supported structured data for actual visible claims; no invented review ratings. Google says no special structured data is needed for generative AI. A nosnippet directive can prevent Google Search snippet eligibility and therefore affect AI Search linking; never set it accidentally.

## Source verification
Atomic factual assertions need relevant original body and date/product/locale, correction state, counterclaims and actual test. A JSON support_status = supported is self-reported until independently checked. If an official source is inaccessible or ambiguous, answer UNKNOWN and block consequential claim rather than creating a plausible number.

## Failure injection and evaluation
Test out-of-date numbers, wrong locale, units, missing prerequisite, ambiguous question, unsupported output, wrong/broken JS, inaccessible forms, misleading how-to and a result claiming to succeed while bytes are corrupted. Verify task success (or honest explicit limitation) and actual rendered content. Citation/rank remain unknown without real external observation.
