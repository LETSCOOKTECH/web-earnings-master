# Tier-1 AdSense Tool Website — Market Decision Record (V34)

**Research snapshot:** 2026-11-26, 20:17 IST onward. **Scope:** one English-language AdSense-first *website*, targeting US first; UK, Canada and Australia are planned geographies **not yet separately volume-verified**. **Status:** CONDITIONAL_G0_DISCOVERY_ONLY — no domain purchased, deployed website, authenticated Google Ads demand export, independent user benchmark, AdSense approval, revenue or ranking verified. This is a durable source-backed decision hypothesis, not an assertion that we found a guaranteed traffic winner.

## Executive decision

**Provisional winner: browser-local Image Compatibility & Repair Studio**. First user job: take iPhone HEIC/HEIF, WebP and AVIF files that a recipient/application cannot open, convert safely into usable JPEG/PNG/PDF, inspect color/orientation/alpha/metadata effects, and export a real corrected file. A generic converter is NOT the product differentiation.

**Secondary option:** focused home-project material estimating (gravel/mulch/pavers) if image competitors beat our planned oracle. **Third:** work-hours/timesheet audit; **fourth:** merchant CSV preflight (stronger specific pain; unverified aggregate search ceiling). We explicitly do **not** declare any of these easy to rank.

A very high-demand query does not make a new domain capable of earning it. The objective is *reachable Tier-1 organic clicks × valid monetized pageviews × actual RPM, net of costs*, with independently successful user tasks as a prerequisite.

### Why not launch Merchant CSV Preflight first?

The prior recommendation was based on **pain**, not validated high-tier-one search reach. Shopify documentation and merchant complaints establish a problem, but not the number of reachable ad-supported searches or ranking opportunity. It remains an engineering-worthy product concept; it loses **this specific AdSense traffic-first selection** until a scoped Keyword Planner export establishes addressable queries.

### Why image compatibility can still fail

Competition already offers **free/no-upload/batch HEIC→JPG** (OfflineConvert, HEIC.dev, NoHEIC, Vinora). Image conversion is not a new category and local processing is **not** a defensible advantage by itself. A user's browser/OS may already solve the job. The claimed market could be inaccessible to a new domain with weak links. We may NOT publish a huge permutation of equivalent format pages as a shortcut.

The only defensible hypothesis is **compatibility confidence**, measured as successful outputs on edge-case files incumbents mishandle: orientation, metadata policy, transparency flattened predictably, ICC/color correctness, corrupt file explanation, multi-image HEIC and large mixed batches. These are **hypotheses**, not observed competitor failures. If three competitors pass the same independent oracle, do not build the same product.

## 3. The experiment that decides real GO vs NO-GO

**Stage A — original demand receipts:** Authorized Keyword Planner or legitimately licensed export for US/GB/CA/AU queries. Store keyword, country, language, device/date window, actual provider metric name, exact match/close variants and source version. Validate *real clicks per search*, not only searches. Check ranking results and AI-Overviews for top tasks; separate competing formats and number of results actually requiring a click. **No ad CPC-to-publisher RPM conversion.**

**Stage B — competitors:** At least FreeConvert HEIC page, OfflineConvert, HEIC.dev, plus OS native workflow as nonwebsite alternative. For each, run an independent test oracle with identical real files: standard color iPhone HEIC, HEIC with EXIF orientation, ICC/P3, alpha WebP, animated WebP (reject/first-frame explicitly), multi-frame HEIF, corrupt/truncated, 100 mixed files, duplicate filenames, non-ASCII filenames, mobile-memory limit. Preserve time/date, device, output hashes, visual/color checks and downloadable artifacts. For strong incumbent successes record them honestly. Verify upload behavior with browser network inspection, not home-page claims.

**Stage C — human task validation:** 10 or more observed, consented Tier-1-target user sessions or rigorous substitute with genuine artifacts. Record task trigger and expected successful file, latency, friction, tradeoffs and *which tool the user already prefers*. No false "100 users interviewed" from Reddit posts. If users have no meaningful trouble, reject.

**Decision gates (all mandatory before production expansion):**
- Real demand in at least one explicit target region at a level justified by expected CAC and CPM, not merely a provider's HIGH label.
- 3+ independently tested alternatives with reproducible **material** gap.
- Independent conversion output oracle and satisfactory iPhone/Windows/WebKit/Firefox/Chrome testing.
- The site offers a clearly different completed user task with no dark pattern or mandatory account.
- AdSense-first unit economics plausible under 0-to-low scenario and legal/licensing risk reviewed.

No arbitrary 70/100 or 10/10 score is a substitute for these artifacts. Until gates pass: **NO PUBLIC SCALING / NO EARNINGS FORECAST**.

## 5. AdSense economic viability and stop-loss

Google page RPM = (estimated AdSense earnings / actual pageviews) × 1,000. Three **hypothetical, not observed** page RPM cases, all USD:
- 10,000 pageviews: at $0.50 RPM => $5 gross; $2 RPM => $20; $5 RPM => $50.
- 100,000 pageviews: $50 / $200 / $500 gross.
- To gross $1,000/month: 2,000,000 / 500,000 / 200,000 monthly pageviews respectively. This is before expenses, invalid traffic adjustments and taxes.
- One-page conversion tasks can produce low pages/session; a large keyword pool does not equal 100,000 pageviews.

**Stop-loss:** Do not fund paid keyword research, high-memory backend transcoding, a domain portfolio, or hundreds of content pages solely from these scenarios. Enforce observed fixed/marginal costs, codec license compliance and policy review. No forced ads near file, convert, copy or download controls. Never auto-refresh or pay for incentivized ad interactions.
