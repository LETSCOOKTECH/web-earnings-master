# Opportunity Intelligence — browser-first market validation engine

**Owner:** 48th skill `web-opportunity-intelligence`. The goal is to avoid investing coding tokens in an unverified idea. Its value is the *decision*, not the number of websites scraped. It integrates public primary evidence, authenticated data where permitted, validated human problems, competitive task testing, development economics, and a low-cost falsification plan.

## Six independent evidence pillars
1. **Demand** — actual scoped owner analytics, normalized Google Trends chart or properly labeled licensed keyword volume estimate.
2. **Human pain** — several independent origin contexts reporting a specific current user job; public posters are not identity-verified.
3. **Competition** — live SERP/current competing tools tested using same permissible inputs; screenshots do not prove output.
4. **Distribution** — plausible way to obtain first qualified human task completions, not simply high estimated keyword volume.
5. **Feasibility** — exact task oracle, input/output bounds, privacy, security, owned/browser/cloud processing, realistic implementation skill/time.
6. **Economics** — incremental per-job cost, hosting, support, legal/licensing, acquisition and actual/assumed revenue clearly separated.

## Workflow stages
**Triage:** stop bad ideas cheaply, zero paid credits; small permitted sources and top constraints. **Desk research:** independent demand/pain/competitor evidence with limited GUI exports. **Deep validation:** top finalist only, current direct tests plus cost and acquisition strategy. **Pilot:** owner-approved real test with actual user success evidence before large build.

## Hard distinction
- Source-link collection != first-party verified page body.
- Having a logged-in browser != blanket license for automated scraping.
- A 0–100 Google Trends series != monthly query volume.
- Semrush traffic estimate != competitor Analytics.
- A public Reddit user statement != authenticated unique human.
- Multiple comments from one viral thread != independent demand.
- A high opportunity score != verified market fit.
- Local test passing != actual account access, real user pilot or profit.

## Execution
`npm run audit:opportunity` validates the example shape and reports incomplete evidence. `node --test tests/opportunity-intelligence.test.mjs` exercises evidence, independence, provenance, cost and unsafe decisions. The Node verifier never opens websites or spends API units. Actual browser task execution is the responsibility of the user's authorized Codex/Computer Use runtime.

## Delegation boundaries
Use existing `web-niche-validation` for market structuring, `web-competitor-audit` for same-input teardown, `web-traffic-hunter` for acquisition pilots, `web-technical-seo` and `web-generative-engine-optimization` for search eligibility, `web-unit-economics-finops` for actual cost, and `web-product-spec` only *after* decision gate. Research should not recursively invoke every skill; pick the next consequential check.
