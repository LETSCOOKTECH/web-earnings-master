# Dominant Tool Creator — decision and execution contract

The objective is not maximum number of skills or pages. The objective is a real user completing a well-defined job with a verifiably correct result on a sustainably affordable and discoverable website.

## Executable phase contract
G0 Access: enumerate user rights, available tools, budget, inputs, privacy and existing deploy authorization.
G1 Demand: exact human problem, independent source origins and dates, original complaints, Trends/third-party estimate units, strongest reasons to reject.
G2 Competitor: identical legal task fixtures tried in real incumbent products; actual result, UX/cost/privacy, evidence of superiority and weaknesses; preserve when incumbents beat us.
G3 Product: stand-alone requirement and exact result oracle, accessible controls, error/empty/loading/offline states and a single primary action.
G4 Architecture: static browser, Worker, WASM, bounded server/API, storage/queue or AI model selection. Prove why cost, device, security and scale constraints support the choice.
G5 Build: installable Astro when warranted, reproducible lock, original useful pages, built output and deterministic core. No placeholder tools.
G6 Verify: independent exact output, malformed/hostile/maximum loads, real browser action, security/accessibility performance, screenshots and file hashes; no yes-by-default manifests.
G7 Release: user permission, owned public HTTPS, actual DNS/TLS, deployed commit, served bytes/404/worker/CSP, rollback and monitoring. Building with SITE_URL does not deploy anything.
G8 Discovery: current provider source originals, public indexability and original task value, real owner Search Console/Bing, authentic AIO/ChatGPT/Perplexity answers; citation vs endorsement separate.
G9 Outcomes: qualified humans and completed jobs, validated policy/consent, publisher account status and net operating margin. No invented visitors or ad RPM.

## Stage-based review statuses
REJECTED, RESEARCH_REQUIRED, LOCAL_PRODUCT_VERIFIED, BUILD_ONLY_NOT_DEPLOYED, EXTERNAL_HTTP_OBSERVED, EXTERNAL_BUSINESS_OBSERVED.
Real online site is not implied by source, a synthetic domain, build, canonical, browser localhost or GitHub Pages repo source. Each stage requires its own independently traceable evidence.

## Input/output evidence packet
One product brief with per-source URLs and actual passages; exact user task; competitor report with same-input fixtures; dated ADR; real implemented code and independent oracle; browser evidence; legal/security/privacy budget; original-domain publishing manifest; external GSC/model/publisher observations only if authenticated. Deliver both positive and negative records. Never only score a keyword list or author an SEO article about a nonexistent tool.

## Agent cost and risk behavior
No account signup, protected site scraping, paid APIs, public deployment or secrets without permission. Keep the project focused on the user job; static where possible. For bugs, skip broad market research and fix the observed failure with a regression test. For idea research, do not build infrastructure before finding credible demand. User demand, SEO eligibility and revenue are independent outcomes.

## Gate failure examples
Google Trends 70 claimed as 70,000 searches/month; copied forum complaints counted as 12 unique users; Astro page with disabled button called complete; HTTP 200 on localhost claimed publicly deployed; robots/sitemap canonical on example.org interpreted indexed; synthetic AI screenshot called positive ChatGPT citation; ads slot called AdSense approved; AI token model with unlimited per-visit spend. Reject these even if a manifest otherwise passes.
