# Runtime integration status
The host-owned execution boundary is a library, not a Codex interceptor. Only registered adapters called through it are covered. Host code must own limits, handler registration and authorization; never expose arbitrary shell/network execution as a read-only capability. Reservations must be upper bounds enforced by the adapter before provider execution. Usage reports are not independently authenticated. Failure consumes the full reservation. The boundary is in-memory and does not survive restart; do not use it as a financial ledger or cross-process quota service.
Consequential assurance CLI decisions now require local artifact verification automatically. Source freshness windows are conservative screening defaults, not proof of effective provider policy. Neutral, contradictory, stale and snippet-only observations do not qualify as supporting evidence.
Remaining: durable budget journal, trusted external approvals, real provider adapters, claim-level evidence lineage, independent benchmark and commercial pilot. Do not label these implemented.
