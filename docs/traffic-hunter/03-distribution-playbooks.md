# 03 — Execution playbooks: high-value channel-native distribution

The objective is to make a working tool discoverable **in the exact moment and context where a user needs it**. No playbook creates guaranteed reach.

## Playbook A — Search demand to useful tool URL
**Inputs:** task query cluster and verified search features in target country/device. **Asset:** working canonical page, accurate upfront capability and limitations, real screenshot, no signup trap. **Actions:** map distinct user intents, test competitor outputs, provide faster/safer/better functionality, create truthful title, crawlable body, internal links, GSC/Bing verification. **Evidence:** nonbrand clicks, SERP impressions by country, actual tasks; query position alone is not profit. **Stop:** thin duplicates, fake ratings, fabricated claims, link spam, or bad output. **Owner handoff:** technical SEO + keyword intent skills.

## Playbook B — YouTube demonstration funnel
**Inputs:** visible user task with satisfying before/after or 2–5-minute detailed method. **Asset:** real screen recording with honest result, limitations and separate relevant destination page. **Actions:** show the problem immediately; title and thumbnail express a truthful promise; explain the workflow, disclose sponsorship, link where platform permits, add accurate timestamps/subtitles if appropriate. Use video-native metrics for discovery, owned-site data for visits; do not infer site acquisition from views. **Stop:** fake output, clickbait, deceptive redirect, re-uploaded unlicensed media, automated engagement. **Evidence:** creator Studio metrics, outbound landing sessions, successfully completed jobs.

## Playbook C — YouTube Shorts / Reels / TikTok / Pinterest
**Inputs:** an easily demonstrated transformation or high-salience mistake with visual explanation. **Asset:** short honest capture, alternate ratio layouts and on-screen real product output; original Pins, not repetitive mass variants. **Actions:** adapt to platform-native constraints, label the tool and link in permitted destination, measure profile/outbound clicks separately. **Stop:** collecting vanity followers if no visits, bulk duplicate Pins, unlicensed music, misleading captions, incentivized views. **Special:** Pinterest Pin clicks differ from Outbound clicks; use the latter plus owned referral sessions.

## Playbook D — Relevant Reddit/forum help
**Inputs:** an actual recent question where we can solve the task better. **Asset:** self-contained useful troubleshooting answer with reproducible steps, alternatives, and transparent affiliation if link allowed. **Actions:** read specific community rules, contribute normally, answer without a link when possible, share a relevant example only when allowed. **Stop:** thin promotional comments, many accounts, bought votes, engineered reciprocal mentions, automated engagement, repeated pitches. **Evidence:** accepted help, genuine feedback, opted-in referral and task completion; not comment count.

## Playbook E — Hacker News Show HN
**Precondition:** working developer-interest tool with a readable original explanation. **Owner:** real human writes and posts on HN; **never AI-generated HN posts/comments or automated posting**. Document genuine technical innovation, license/privacy/runtime tradeoffs and request honest feedback without vote requests. **Evidence:** actual feedback, feature requests, usage, not the number of upvotes. **Stop:** artificial votes, resubmits, sensational titles and bot campaigns. Primary HN guidelines apply.

## Playbook F — Product Hunt
**Precondition:** product is working, public and ready for first users. Prepare listing, gallery demo, founder identity and a landing CTA. Seek genuine feedback or sharing rather than votes; Product Hunt expressly forbids requesting votes and vote incentives. Track referral as a pilot, not ongoing recurring traffic guarantee. **Stop:** vote exchanges, giveaways conditioned on votes, fake makers, inflated claims.

## Playbook G — GitHub + developer adoption
**When:** tools have a legitimate reusable CLI/API/library, not a repo created solely to attract backlinks. **Asset:** documented public package, correct examples, changelog, tests, accessible license/terms, clear external demo if appropriate. **Actions:** use real topics and a truthful README, answer issues, maintain integration and security, publish releases; respect every registry's distribution rules. **Evidence:** real package usage where measurable, opted-in demo referrals and validated tasks. **Stop:** package squatting, SEO-stuffed READMEs, forced backlinks, insecure samples, using private user data for telemetry.

## Playbook H — Institutional/editorial distribution
**When:** exact form or compliance problem with proven public requirement; e.g., student application limits. **Asset:** public responsible how-to, valid and low-risk tool, tested before/after. **Actions:** discover public institutional help resources, check need, contact official/editor where appropriate with one highly relevant demonstration and disclose affiliation, offer documentation without demanding links. **Evidence:** independent editorial recommendation and human task usage. **Stop:** impersonating government, claiming approval, sending bulk unsolicited emails, exchanging money for editorial SEO links.

## Playbook I — API, embed, plugin, MCP
**When:** repeated integration solves a problem without forcing website visits. **Asset:** correct callable API, auth, quotas, SDK/docs, signed privacy policy and versioning. **Actions:** integrate into tools where users already work; provide real usage telemetry with permission, docs and support. **Evidence:** successful authorized operations, retained integrators, justified paid API revenue; agent executions may yield no display-ad pageviews. **Stop:** insecure auth, unbounded compute, automated attribution links, tying an essential workflow to link clicks.

## Playbook J — Newsletter and creator/partner collaboration
**When:** meaningful updates or repeated need. **Asset:** optional opt-in subscription, genuine new release or tested content; signed partner scope and disclosure. **Actions:** build consent and unsubscribe management, send only the promised content, track sent/delivered/clicked/converted separately; do not purchase scraped addresses. Creators must disclose material relationships. **Evidence:** opt-in subscribers, validated jobs, unsubscribes, attributed spend. **Stop:** spam lists, hidden sponsor agreements, missing suppression lists.

## Playbook K — Paid acquisition pilot
**When:** product validated and baseline per-success margin exists. **Asset:** nondeceptive landing page and measurable high-intent ad, fixed budget stop; ads not placed deceptively next to controls. **Actions:** pre-set allowed geos, daily cap and source tracking, examine ad network and AdSense invalid traffic conditions, optimize for completed tasks rather than cheap clicks. Paid channels may be uneconomic for a pure low-RPM ad-funded utility. **Stop:** suspicious traffic spikes, unverified vendor, negative contribution without learning justification, hidden incentive or redirection.

## Playbook L — Cross-tool compounding and repeat
**When:** a natural second task follows first, such as resize → compress → format conversion. **Asset:** zero reupload transitions, stable presets, transparent export and honest recommendations; link only between useful relevant products. **Evidence:** additional tasks **not** fake extra pageviews, voluntary returning jobs, earned links and referrals. **Stop:** forced extra pageviews or ad impressions, unrelated domain swaps, bait-and-switch.

## Production-style outreach checklist (no auto-sending)
For each legitimate outreach: who owns the original problem, where rule permits contact, one-sentence verifiable benefit, proof URL, exact CTA and disclosure, no exaggerated outcomes, no mass template blasts, follow-up only when lawful and welcome. User/owner approves the actual message and destination. If not permitted, record no-action.

## Failure patterns
- Viral video, no referrals: likely entertainment-only interest; revise task CTA and landing fit, not viewer manipulation.
- Community referrals, no completions: test exact input and mobile; possible expectation mismatch.
- Strong content, slow growth: check where users already solve the problem and experiment with native format rather than reposting.
- Paid clicks, no sustainable ads: review cost per valid job, consent mix, gross vs net, spam/IVT risk and pause.
- Big AI citations, no sessions: the answer may satisfy intent without click; prioritize executable job/comparison evidence not citation score.
