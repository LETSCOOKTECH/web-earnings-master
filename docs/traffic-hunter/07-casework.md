# 07 — Worked cases for Sense Ecosystem

Illustrations below are **synthetic scenario plans**. All volumes, costs and scores must be populated from actual measured data; no user visits, publisher revenue or conversion rates have been observed for these examples.

## Case A: Browser-local image compressor with 50 KB target
**User job:** Applicant needs a file small enough for a real upload form, but image needs to remain acceptable and private.
**Prerequisite validation:** exact target file-size result is achievable on supported inputs; truthful failure state if impossible; no upload claim verified with network inspection and device tests; accessible mobile workflow; no misleading ad near Download.
**Hunter signals:** current genuine public application requirements, questions about photo size, forum pain around quality loss, YouTube before-after demonstration demand, original codec benchmarks.
**Candidate channels:** localized task search, narrow how-to screen recording, actual exam/help resources after verifying official limits, image tutorial Pins, permitted context-specific Q&A.
**Counterchannels:** generic viral comedy account, unrelated tech subreddit, mass Pinterest duplicates, fake government endorsement, cheap paid view vendors.
**Native assets:** reproducible privacy/network experiment; tested size–quality trade-off table; 45-second tutorial with exact result; links to the actual distinct processing tool.
**Pilots:** (1) tested task page query and relevant support resources; (2) honest video with clear permitted link; (3) institutional resource only when a real editor sees utility. Score each without inventing impressions.
**Metric:** completed image export satisfying width/height/KB constraints from actual human sessions; source confidence; failure reasons.
**Stop:** invalid dimensions, private photo leakage, misleading claims about compression quality, suspicious traffic.
**Business note:** single-task low pageviews may make ads weak; prioritize cheap client-only compute and real session quality, not click manipulation.

## Case B: Browser/network privacy diagnostics
**User job:** User cannot determine why a browser, ISP or site is slow or blocked.
**Prerequisite:** measured metrics accurately labeled (e.g. browser-visible tests vs true bandwidth), privacy minimized, confidence and errors reported.
**Signals:** technical troubleshooting forums, GitHub issue reports, help communities, developer discussions of difficult-to-reproduce failures.
**Channels:** self-contained troubleshooting docs, helpful coding answers, maintained public test-case repo, developer videos, earned independent link/reference from network troubleshooting guides.
**Metric:** valid diagnostic run and actionable remediation adoption, not merely page opens.
**Counterhypothesis:** same result can be provided by an existing tool with more trust; users won't share diagnostic artifacts that expose their IP or private network.
**Stop:** collecting identifiable traffic without explicit need, claiming exact ISP policy or network identity without verifiable methods.

## Case C: Freelance invoice utility
**User job:** Create a reliable invoice with accurate regional tax and secure export.
**Prerequisite:** correct local tax rules, valid arithmetic and privacy, no fake legal certification.
**Channels:** freelancer/creator tutorial, helpful resource for a genuine local business group, spreadsheet integrations, bookkeeping partner, targeted search and maybe small paid acquisition if actual paid conversion margin justifies.
**Metric:** valid invoice exported, repeat invoicing within the defined cohort; not simply 1,000 template views.
**Failure:** incorrect tax assumptions, forced registration, low-margin paid acquisition, fake accountant endorsement.

## Case D: A sudden competitor shutdown
**Trigger:** first-party announcement that a known tool will retire or restrict functions.
**Don't infer:** all former traffic shifts to competitors or to our new website.
**Actions:** verify official end date, capabilities changed, actual affected users and their alternatives; build genuine working alternative and transparent comparison; measure search and qualified referral demand.
**Stop:** opportunistic landing page claiming to be the retiring brand, trademark confusion, pretending to import/transfer accounts without authorization.

## Case E: 1,000 visits become 10
**Do not default to "Google penalty".** Step by step:
1. Confirm site analytics same metric, date range, country, referral definitions and bot filtering.
2. Check whether prior 1,000 visits were one-day social burst, one source, fake/low-quality purchased traffic, discovery feed or real recurring human usage.
3. If organic: inspect Search Console indexed state, impressions, queries, click changes, geo/device/feature and any owner manual actions.
4. If social: check source campaign expired, policy, outbound link changes, platform reach vs owned sessions.
5. If paid: campaign ended/spend cap exhausted, not a ranking loss.
6. If Direct: possible lost attribution and browser/app behavior. Do not allocate unknown to AI or organic.
7. If visits existed but no tool starts: inspect promise and errors; perhaps traffic never had proper intent.
8. Define exactly one hypothesis and test a relevant recovery route, tracking validated jobs.

## Decision example (NO manufactured results)
Candidate: a relevant exam help guide, current rule confirmed, tool validated, voluntary webmaster review permitted, baseline task funnel instrumented. Its score may be high **as a qualitative opportunity**, but it is not eligible for an 'approved traffic source' claim until the actual page is published, traffic is observed and user tasks succeed.
