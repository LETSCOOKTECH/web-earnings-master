# Traffic Hunter — sustainable qualified acquisition operating system

**Edition:** 2026-11-23. **Scope:** new skill #47 in Sense Ecosystem/Web Earnings Master. Applies to website and browser-tool portfolios across markets. No affiliate traffic purchases, click-bot experimentation, or artificial referral campaigns.

The system is an **acquisition decision engine**, not a spam machine or secret ranking exploit. It turns sources of human need into candidate distribution opportunities, then into deliberately small channel-native experiments, then into validated task completions and measured economics.

## Core causal graph
Problem/need signal → relevant discoverability channel → seen impression or referral opportunity → actual click → qualified landing session → valid tool start → validated result → voluntary return/share → legally monetizable human usage → reconciled contribution. Each arrow can fail. An AI citation, developer package install, video view or search impression is **not** a site session. Server/bot requests are not legitimate publisher ad traffic.

### Owned vs earned vs paid vs partner
- **Owned:** accurate tool pages, documentation, newsletter to consented readers, RSS, help center, voluntary saved links or presets.
- **Earned:** search/index result, AI citations, editorial mentions, personal community recommendations, GitHub stars or code references (not equal to visits), independent comparisons, organic video discovery.
- **Partner:** relevant integration, institution help desk, maintained library guides, permitted plugin catalogs, co-marketing with explicit terms, creator tutorials with disclosure.
- **Paid:** carefully controlled search/social sponsorships when user economics support acquisition; source-level tracking and publisher invalid-traffic review required.

## Programmatic interfaces
- `scripts/evaluate-traffic-hunter.mjs` accepts a JSON manifest and outputs status, transparent channel ordering and warning signals. It does not send messages, post, buy ads, scrape websites or make network requests.
- `templates/traffic-hunter/opportunity-plan.example.json` is a **synthetic, intentionally unapproved** candidate list to demonstrate validation.
- `templates/traffic-hunter/experiment.example.json` is a **synthetic** experiment receipt schema.
- `tests/traffic-hunter.test.mjs` exercises invalid traffic flags, attribution, unit-economics and invalid manifest cases.
- `sources/traffic_hunter_sources_2026_11_23.json` distinguishes directly opened official docs from source leads needing verification.

## Dependency and authorization model
1. Build target URL working correctly, with primary task tested.
2. Use fresh public research, authorized analytics, and independent sources for opportunities. On services with login/publishing, human authorizes each publication, promotion, spend and collaboration.
3. No unauthorized social platform scraping. No unattended community posting. No use of other people's personal data or account credentials for growth.
4. Verify policy before every action and record a reproducible event/expense/outcome.
5. Only scale repeated high-quality conversions with a viable cost ceiling. If revenue is unobserved, label economics **UNKNOWN** rather than assuming $0 or positive ROI.

## Definition of mature
Complete research coverage and passing local fixtures mean the **library is executable and auditable**. A deployed property must separately demonstrate first-party source permissions, an actually working product, real user acquisition, safe ads, valid consent and measured economics. Cannot claim 'production traffic acquired' from this repository.
