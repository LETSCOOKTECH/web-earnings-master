# 02 — Opportunity hunting: find real unmet needs before distributing anything

## Why traditional lists of traffic sources fail
A channel with 100 million users provides no benefit if our exact audience is absent, the platform forbids promotion, the landing workflow fails, or visitors cannot complete the task. The unit of opportunity is **specific user job × available discovery moment × permissible useful asset × observable resulting task**. Reject 'post on 50 sites' as a strategy.

## The repeatable signal-hunting loop
1. **Job vocabulary:** start from a task such as "reduce passport photo below 50 KB without upload" or "bulk convert HEIC to JPG offline". Collect meaningful synonyms, local terminology, required output constraints, common browser/device failures and other genuine workarounds.
2. **Find live conversations:** authorized Google/Bing searches, visible social search, topic-specific forums, developer issues, GitHub issues where permitted, developer docs, FAQs, product reviews, YouTube comment themes, public university help pages, changelogs and search console owners' data. Read current community policy before engagement. Do NOT harvest people or personal emails.
3. **Classify pain:** immediate blocker, bad existing solution, unexpected fee, unsafe upload, compatibility/size issue, regulatory submission requirement, slow workflow, or a recurring repetitive job. Record the original URL/text excerpt without copying sensitive content; date and jurisdiction.
4. **Look for a credible wedge:** faster verified solution; documented privacy; exact format target; bulk UX; local-language correctness; accurate reproducible benchmark; useful open integration; accessible mobile flow.
5. **Identify venue-native value:** search result → working task page; YouTube → screen capture with honest before/after; technical forum → complete self-contained answer; university help guide → reliable instructions; GitHub → maintained library; Pinterest → original visual use case; AI citation → real data table and methodology.
6. **List reasons to disbelieve:** abandoned discussion, community rule prohibits links, outdated complaint already resolved, competitors solve it now, target audience rarely clicks links, our tool cannot fulfill promise, time/cost too high, referral is undercounted, ad network cannot monetize.
7. **Observe actual pilot evidence:** begin from an authorized small low-risk experiment, record venue/version/time/country, traffic source quality and completed job, then compare alternative source hypotheses.

## Emerging opportunity detectors
- **Breaking user requirement:** an exam/job application or marketplace changes photo/picture file size. Verify the responsible institution's *original* current specification, not a social screenshot, before publishing a tool preset.
- **Product withdrawal / migration:** established product changes prices, free limits or APIs. Verify official first-party notice, end date, current alternatives and our tested capabilities; never conclude that former user traffic automatically transfers to us.
- **New format / browser support:** codec update yields real incompatibilities. Require spec/browser support evidence, output fixture and compatibility test.
- **Workflow bridge:** two established products lack smooth export/import; build a legitimate converter and reusable SDK.
- **Search feature:** ranking page earns impressions but not meaningful clicks; avoid investing in zero-click facts, focus on task outputs AI text cannot perform.
- **Institutional constraint:** public guide repeatedly recommends a workaround; offer direct improvement only if accepted by the institution, with transparent privacy.
- **User education gap:** people misuse a technical parameter; create real tested explainer plus tool.
- **Seasonal spikes:** background changes by country or academic cycle; pre-plan if historical patterns and exact year requirements confirmed.

## Evidence classes
P1: owned first-party analytics or observed product/task receipt (not public benchmark).
P2: current first-party platform policy, public product specification, original institutional requirement, or verified public post.
P3: licensed modeled search/competitor dataset (includes sampling assumptions; not owned traffic).
P4: anecdote or interpreted signal needing reproduction.
U: unavailable, uncertain, unauthorized or stale. U never silently becomes proof.
Search engine inferred ranking behavior cannot be converted into a 'probability we rank' number.

## Transparent ordinal scoring
Project-only qualitative 0–5 evidence-backed factors; never claim vendor algorithm:
- 25% audience/task fit
- 20% believable source-native value asset
- 15% feasible permission/reachability
- 15% estimated execution effort & time-to-feedback
- 15% measurable real task success
- 10% reusable asset/compounding potential

Scores must be accompanied by supporting notes, source URL and counterhypothesis. Permission/AdSense safety is a **hard gate**, not a weighted penalty. A high score cannot override prohibited methods.

## Qualification decision
1. BROKEN_PRODUCT: no promotion.
2. POLICY_UNVERIFIED: research/plan only.
3. NO_RELEVANT_AUDIENCE: reject unless evidence changes.
4. ASSET_UNREADY: build demo/benchmark before outreach.
5. SOURCE_MEASUREMENT_UNKNOWN: pilot only with conservative instrumented landing.
6. READY_TO_TEST: owner-approved, bounded experiment.
7. REPEATABLE: compare multiple cohorts and cost before expansion.

## Defensibility test
How many people could use this if all search/social referrals disappeared tomorrow? Would anyone bookmark/recommend or integrate it because it actually solves the task? If the answer is none, distribution may simply amplify a weak product.

## Required opportunity record
`signal_id`, `observed_utc`, `source_url`, `platform`, `user_job`, `evidence_type`, `context`, `opportunity_hypothesis`, `counterhypothesis`, `asset`, `destination_url`, `fit`, `policy_review`, `predicted_cost` (assumption or actual), `primary_metric`, `disconfirm_condition`, `owner_approval`, `decision`. Never capture user contact lists, cookies, private files or inaccessible account data.
