# Sense Dominant Tool Creator — master execution skill

**Mission:** Select and produce a valuable working web utility with verifiable user output, sustainable costs, differentiated experience and honest SEO/AI eligibility. This is an orchestrator of specialist skills, NOT a substitute for them. Never produce a dead demonstration link, pretend an attractive form is a functional tool, or invent market/search/publisher outcomes.

## Trigger and scope
Activate for: build a premium SEO-first web tool, create an Astro project from research, identify high-demand utilities, turn a concept into a deployed tool site, audit a whole tool-business pipeline or improve market/technical/AI visibility together. Skip unnecessary phases for a bounded bug or a single SEO audit. Astro is an option, not a mandatory architecture. Read docs/creator/00-orchestration.md first, followed by only task-relevant domain references.

## The 10 required outcomes and routing
1. **Permission and task:** Identify the real job, inputs, independently provable outputs, audience/country/device, rights, cost limit and owner permissions. Delegate user story to web-product-spec.
2. **Falsify demand:** Independent originating pain sources; typed Trends/keyword metrics; present substitute and strongest negative evidence. Invoke web-opportunity-intelligence, web-keyword-intent, web-niche-validation. No guessed volume, traffic or market size.
3. **Test competitor:** Reproduce identical permitted inputs, result correctness, UX limitations, pricing and privacy for actual relevant tools; record when competitors are better. Invoke web-competitor-audit.
4. **Choose architecture:** Use web-workload-architecture-router, web-browser-compute, web-unit-economics-finops, web-astro-engineering. Static+Worker for bounded browser tools; API/queue/DB only for real server needs. Document budgets, security and rollback.
5. **Specify product:** Actual correctness oracle before code, meaningful copy and user limitations, compact professional responsive UI, accessible errors/states and trust boundaries. Invoke web-frontend-experience-engineering and web-accessibility-agent-ux.
6. **Implement:** Produce an INSTALLABLE project with pinned lockfile, tested source modules, functioning transformations and reliable file/API outputs; route to web-fullstack-production-executor, web-backend-api-engineering and web-product-validation.
7. **Adversarial test:** Build/type check, independent exact-output tests, malformed/security/size edges, real Chromium/Firefox/WebKit browser operations, no-JS explanation, privacy egress, keyboard and responsive QA, performance on stated workload. Invoke web-security-assurance-asvs, web-scale-reliability and web-launch-review.
8. **Actual launch:** Owner permission, real DNS/TLS/public HTTPS, deployed checksum, live user action/404/robots/canonical/WAF, cost alerts and rollback. Invoke web-domain-operations, web-release-observability-operator. No protected repo exposed without explicit permission.
9. **Search and AI discovery:** Check real index/crawl controls and original page value, provider-specific real SEO/AI answer captures and link/citation/recommendation distinctions. Invoke web-technical-seo, web-aeo-answer-optimization, web-generative-engine-optimization, web-dominant-recommendar. Google does not require magic llms.txt or AI schema. No proprietary #1 formula.
10. **Real acquisition and profit:** Track qualified referrals, task completion, privacy-safe metrics, owner publisher eligibility/consent and real revenue less cost. Invoke web-traffic-hunter, web-search-analytics, web-publisher-policy-eligibility, web-unit-economics-finops. Never call synthetic RPM actual earnings.

## Decision gates
- REJECT / RESEARCH_REQUIRED / CHEAP_PILOT when evidence of user need, differentiation or distribution is inadequate. A research ledger with URLs is not independently authenticated demand.
- LOCAL_PRODUCT_VERIFIED only after real output and negative/browser tests passed.
- BUILD_ONLY_NOT_DEPLOYED when a compiled bundle exists but no verified owned public host exists.
- EXTERNAL_HTTP_OBSERVED requires independently checked owner-authorized real DNS/TLS, exact served version and functional browser behavior on that deployed URL.
- EXTERNAL_BUSINESS_OBSERVED requires independent genuine GSC/Bing/provider/analytics/publisher evidence. A static file cannot establish it.

## Real Astro starter usage
Read docs/creator/02-astro-build.md and current docs.astro.build. Start from examples/astro-tool-starter, which demonstrates a real JSONL validation and normalization tool. In its folder run npm ci, npm run check, npm run build, npm test and npm run test:e2e after installing the Playwright browsers. Run npm run verify:build on the actual emitted output. REQUIRE Node version supported by the pinned Astro dependency. A screenshot, a folder of snippets or a placeholder form does not satisfy the user-job oracle. Do not infer public deployment from SITE_URL: the starter intentionally defaults to FIXTURE_ONLY and search exclusion.

## Mandatory tests and evaluator
Run npm run test:creator, npm run audit:creator:brief, npm test, and the dedicated Astro starter CI that performs actual clean npm ci/build/typecheck/Node tests/Playwright. For new tools, add independent data oracles plus intentionally bad cases rather than altering only an acceptance JSON.

Evaluate THIS SKILL by blind unfamiliar tasks both with and without it under identical model/effort/tool budget, independent graders, held-out inputs, user output/UX/security and measured cost. A source count, test count or one demo is not proof of 100x improvements. Read docs/creator/05-evaluation.md.

## STOP AND REPORT
Stop for missing owner authorization, fake/duplicate demand, unverifiable competitor claims, broken user output, critical security/privacy issues, unbounded API cost, missing dependency lock/build, misleading public URLs, unproven AI citations or publisher approval. Return precise blocked gate, verified local artifact and next least-cost experiment. Do not overclaim completion, SEO rankings, traffic, ROI or global production readiness.

## Target artifacts
A product opportunity brief with provenance and dissent; a reproducible rival benchmark; architecture/cost ADR; installable tool; unit/browser/security proof and screenshots; original-source ledger; route and SEO manifests; release/rollback packet; owner-reported search/publisher data if authorized. Preserve negatives and not-run tests.
