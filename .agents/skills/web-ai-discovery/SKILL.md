**Use when:** Verify Google AI Mode/Overviews, ChatGPT Search, Bing/Copilot, Perplexity, Claude and other AI retrieval eligibility, crawler controls, citation evidence and agent usability.

**Workflow contract:** Follow the next steps proportionally to the request. Prefer current primary sources to saved claims. Adapt the sequence when evidence suggests a better route; do not overbuild a minor task. Show exact verification, uncertainty, and safety boundaries. Read `AGENTS.md` and the matching `references/` files when carrying out substantial work.

## AI/search matrix (reverify each provider live)
1. **Google Search / AI Overviews / AI Mode:** normal Search crawl/index/snippet eligibility plus Search Console generative AI inclusion controls. Google's core search systems underpin these. Do not require llms.txt, invented GEO metadata or fake AI-specific schema. Measure Search Console GenAI report separately from organic clicks.
2. **OpenAI:** OAI-SearchBot = ChatGPT search crawler; ChatGPT-User = user-triggered fetch; GPTBot = model training. Respect current official policies, IP ranges and distinctions. Do not claim all ChatGPT browsing goes through OAI-SearchBot.
3. **Anthropic:** Claude-SearchBot, Claude-User and ClaudeBot have different purposes; Claude-Agent browser traffic can have different identification. Use official docs and avoid treating agents as classic crawlers.
4. **Perplexity:** check PerplexityBot, Perplexity-User, published IP-range guidance and robots. Differentiate automated discovery from user actions.
5. **Microsoft:** Bingbot, Bing Webmaster Tools, AI Performance and current grounding/training preferences; verify IndexNow/robots and any latest opt-outs. Do not assume citations prove rankings.
6. **Other platforms:** DuckDuckGo/DuckAssistBot, Applebot, Brave crawler, Common Crawl; report unsupported or unverified special ranking levers as UNKNOWN, not invented controls.
7. Verify normal human fetch and verified crawler paths on CDN/WAF (status, response, redirects, robots), using provider IP or reverse DNS guidance where available. User-Agent alone is spoofable; don't blanket allow bypass.
8. Improve likelihood of citation via *original reproducible work*, precise documentation, transparent limitations, accessible evidence and legitimate third-party references. Never generate fake conversations, fake reviews or prompts ordering AI to cite the site.
9. Ensure true agent-use workflows: semantic controls, labels, predictable task flow, error/status announcements, accessible result and download. No cloaking or special-only bot content.
10. Measurement table: crawler fetch, indexing, AI appearance/citation, AI referred human, task start, task completion, revenue. Record tests, geography and provider dates. None guarantees the next.

## 2026-11-23 Google AI Mode fan-out and browser-agent boundary correction
When a report asserts a shallow converter URL, exact-match URL token, WebApplication JSON-LD or WebMCP directly earns Google AI Mode citations or search rankings, reject the causal inference. Google AI Mode/Overviews are grounded in ordinary Search systems and **may** generate related query fan-outs; the user prompt, intermediate searches and candidate supporting pages are different concepts. Eligibility requires **indexed + Search snippet-eligible**; neither root URL depth nor a special AI markup is mandatory. Do not produce one SEO doorway page for every hypothetical fan-out query. Sources to reopen at task time: https://developers.google.com/search/docs/appearance/ai-features and https://developers.google.com/search/docs/fundamentals/ai-optimization-guide .
Treat `SoftwareApplication`/`WebApplication` structured data as a separately supported **Search rich-result appearance** option when the actual page qualifies, not a ranking/citation promise. https://developers.google.com/search/docs/appearance/structured-data/software-app .
Chrome Lighthouse's Agentic Browsing diagnostics are **experimental (Chrome 150+)** and Chrome WebMCP is a separate experimental agent-interface capability; neither is a mandatory Google Search requirement. If tested, record browser/version, enrollment, fractional pass counts, real agent task completion, compatibility and fallback. https://developer.chrome.com/docs/lighthouse/agentic-browsing/scoring .
Capture five independent numbers: search indexing state; AI feature exposure/appearance; visible supporting URL/citation; actual human referral click; successful completed task. Do not turn other platforms' citations or a speculative "AI cannot convert files" assertion into guaranteed referral. See docs/research/04-user-teardown-google-ai-url-causality-audit-2026-11-23.md.

**Search Console inclusion-control rollout (verified 2026-11-23):** Google's current AI optimization guide requires sites to be included in its generative AI Search features; the Search Console `Settings > Search generative AI` inclusion/exclusion/inheritance control was updated by official Google documentation as **rolled out worldwide as of August 31, 2026**, with inclusion default for top-level properties and inheritance possible for child properties. Earlier cached first-party text described the June UK pilot; treat it as superseded by the later dated August 31 update, but confirm the actual property setting before asserting account compliance. Where the feature is available and the user has authorized property access, verify that the property and closest configured parent are **not explicitly excluded**. Do not silently change the control or infer its state solely from availability in documentation, and do not call it a citation/ranking boost. Unconnected or unavailable account = `UNKNOWN_PROPERTY_CONTROL`. This control is separate from Google-Extended model training choices. https://support.google.com/webmasters/answer/16908024 ; https://blog.google/products-and-platforms/products/search/new-controls-website-owners/ ; https://developers.google.com/search/docs/fundamentals/ai-optimization-guide .
