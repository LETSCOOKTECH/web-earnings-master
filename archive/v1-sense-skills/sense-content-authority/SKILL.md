# People-first content and authority

## Per flagship tool page
Actual interactive task above the fold; concise and accurate description in raw HTML; limitations; privacy/data flow; supported inputs and output correctness; real examples; troubleshooting; related task links. Avoid generic blog filler or arbitrary word count.

## Original research workflow
1. State a useful testable question not answered well by competitors.
2. Use legal/license-clear fixtures; document methods, device/browser, codec versions, sample size, evaluation criteria and failure data.
3. Run experiments and retain actual logs/hashes; publish negative results and reproducibility. No invented figures, “best” claims or duplicate summaries.
4. Expose a stable page, downloadable method/fixtures when safe and licensed, accessible figures and table captions.
5. Share appropriately with relevant developers, educators, technical publications and creators. Ask for independent use, not paid ranking credit.

## Distribution
Useful GitHub libraries, technical demos/videos, responsibly answered community questions, original troubleshooting materials, and genuine integrations. Track referral visits, user completion and continued use. No paid link farms or artificial exchanges.

## Editorial review
Review accuracy, claims, format compatibility, semantic linking, accessibility, references, licensing and actual tool behavior before publication. Distinguish evergreen methods from date-sensitive data.
