# Competitor forensics

## Procedure
1. Build a five-plus-site competitor shortlist using actual ranking pages, not only domain homepages. Include same task, country and device.
2. Inventory product features, restrictions, supported formats, size limits, privacy disclosures, conversion methods, pricing/friction, output errors, mobile behavior and ads. Cite the actual tested page and access date.
3. Create legally usable test fixtures and a controlled protocol: same files/settings/browser/hardware, cold/warm starts and fault cases. Never upload confidential or copyrighted private files to a third-party service without permission.
4. Test observable outputs: actual bytes, MIME/signature, dimensions, alpha handling, legibility/quality, EXIF/privacy, error correctness, partial failures, export ZIP integrity; log any inaccessible tooling.
5. Measure task completion, number of steps, latency distributions, memory failures and self-reported usefulness. Separate observed test results from published marketing claims.
6. Propose a **testable** product advantage, e.g. complete a 40-file batch with consistent verified outputs while preserving quality; then benchmark it. A pretty landing page, private processing or batch processing alone is not novel.
7. File result in `templates/competitor-benchmark.md` and clear decision GO/NO-GO.

## Validity
No “competitor fails” claim without a reproducible case, date and configuration. No automated bulk scraping that violates site terms. Do not assume authority metric is Google's ranking factor. Narrow gap findings expire after competitor releases.
